# のーとびより β 仕様書

> 現行コード（`index.html`）から起こした仕様のまとめです。挙動を変えるものではありません。

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| アプリ名 | のーとびより β |
| 目的 | note の「自分の記事についた未返信コメントの確認」と「お気に入りクリエイターの新着記事チェック」を1画面で行う |
| 構成 | `index.html` 1ファイルのみ（HTML / CSS / JS をすべて内包）。ビルド工程なし |
| ホスティング | GitHub Pages（`main` への push で `.github/workflows/deploy.yml` が自動デプロイ） |
| 外部依存 | note 非公式API、自前 Cloudflare Worker（CORS プロキシ）、公開 CORS プロキシ（予備）、Firebase（Auth / Firestore） |
| 対応画面 | 最大幅 720px の1カラム。PC・スマホ両対応 |

## 2. ファイル構成

```
index.html                  アプリ本体
favicon.png                 ファビコン（※index.html 内は base64 埋め込みを使用）

  ├ src/index.js            Worker 本体
```

## 3. 画面構成

```
┌ ログイン画面（オーバーレイ）
│   ├ Googleでログイン
│   └ ログインせずに使う（ゲストモード）
└ メイン画面
    ├ ヘッダー：ロゴ / タイトル / テーマ切替 / ユーザー情報（ログイン時）
    ├ タブ：［コメント管理］［フィード］
    ├ コメント管理セクション
    └ フィードセクション
```

### 3.1 ログイン画面

- 起動時に全画面で表示される。
- 「Googleでログイン」：ポップアップでログイン。ポップアップがブロックされた場合はリダイレクト方式にフォールバック。
- 「ログインせずに使う」：ゲストモードに入り、ログイン画面を閉じる（データは端末内のみ）。
- Firebase が6秒経っても読み込めない場合は「ログイン機能を読み込めませんでした…」と案内を表示。
- ログアウトするとログイン画面に戻る。ゲスト利用中はログイン画面を再表示しない。

### 3.2 ヘッダー

- テーマ切替ボタン：`🌗 自動 → ☀️ ライト → 🌙 ダーク` の順で切り替え。
- ログイン時のみ表示：Google アイコン、`@noteID`、「noteID変更」「ログアウト」ボタン。

## 4. 機能仕様

### 4.1 noteID の登録・表示

- noteID が登録済みの場合、入力欄を隠して **アイコン＋表示名** を表示（クリックで自分のクリエイターページを新規タブで開く）。
- 表示名・アイコンは `GET /api/v2/creators/{id}` で取得してキャッシュ（`nc_note_profile`）。取得失敗時は `@ID` 表示。
- 「noteID変更」でプロンプト入力。先頭の `@` は除去される。
- ログイン時に noteID が未登録なら、プロンプトで登録を促す。

### 4.2 コメント管理タブ

自分の記事について、**まだ返信していないコメント** を一覧表示する。

#### 取得モード

| モード | 内容 |
| --- | --- |
| 件数指定（初期値） | 最新の公開記事から指定件数（1〜50、初期値3）を取得 |
| 全件 | 2025/9/8 10:00（JST）以降に公開された全記事を取得 |

- 記事一覧は `GET /api/v2/creators/{id}/contents?kind=note&page={n}&per=20` をページングして取得。
- 取得モード・件数は保存され、ログイン時は端末間で同期される。

#### 記事URLでの個別登録

- `https://note.com/{urlname}/n/{key}` 形式のURLを登録できる（他人の記事も可）。
- 登録記事はタグ（📄 タイトル）で表示、`×` で削除。
- タイトルは `GET /api/v3/notes/{key}` で取得して反映。
- 取得時は自動取得した記事に合流（重複は除外）。noteID 未登録でも登録記事だけでチェック可能。

#### 未返信コメントの判定

1. 各記事のコメントを `GET /api/v3/notes/{key}/note_comments` で取得（同時5記事まで並列）。
2. 以下をすべて満たすコメントを「未返信」とする：
   - 投稿者が記事のオーナー本人ではない
   - 返信数（`reply_count` / `sub_comment_count` / `children_count` / 子コメント配列長のいずれか）が 0
   - 「返信済み」ボタンで手動除外していない（`nc_replied`）

#### 表示

- 上部に「未返信」件数のメトリクス。
- コメントカード：アイコン、`○○さんがあなたの記事にコメントしました`、記事タイトル（32文字で省略）、コメント日時。
- カードクリックで該当コメント位置（`?from=notice&scrollpos=comment&c={key}`）を新規タブで開く。
- 「返信済み」ボタンでカードを非表示にし、件数を1減らす（状態は保存・同期）。
- 取得中は「更新」ボタンが「中止」に変わり、押すと取得を中断できる。
- 進捗を `（完了数/全体数）` でステータス表示。
- 未返信が0件なら「最新N件の記事に未返信コメントはありません」（全件モードでは「全N件の記事に…」）。

### 4.3 フィードタブ

登録したクリエイターの最新記事を、クリエイターごとにまとめて表示する。

#### クリエイター管理

- アカウント名（`@` 付きでも可）を入力して「追加」。重複は無視。
- タグの `⠿` ハンドルをドラッグで並べ替え、`×` で削除。
- 並び順はフィード一覧のグループ順にも反映される。

#### 取得

- 各クリエイターについて以下を並列取得（同時4アカウントまで）：
  - 記事一覧：`GET /api/v2/creators/{id}/contents?kind=note&page=1&per=20`（最新20件）
  - プロフィール：`GET /api/v2/creators/{id}`（表示名・アイコン）
- 取得結果は `nc_feed_cache` にキャッシュ。
- 全件取得に失敗した場合は、前回のキャッシュ表示を維持してエラーを表示。

#### 表示

- クリエイターごとのグループ（ヘッダー＋記事カード）。記事は公開日の新しい順。
- グループヘッダー：
  - `⠿` ドラッグでグループの並べ替え（タグ側と共通の並び順）
  - `▼` クリックで開閉（**初期状態は折りたたみ**、開いたグループは記憶）
  - アイコン＋表示名クリックでクリエイターページを新規タブで開く
  - 未読数バッジ（`N件の新着` / `新着なし`）
  - 「全て既読」ボタン
- 記事カード：サムネイル、タイトル（リンク）、公開日、「既読にする / 既読」トグルボタン。
- 既読カードは半透明表示。
- ツールバー：「全記事を既読」ボタン、「既読を非表示」チェックボックス。

### 4.4 起動時の自動処理

1. 保存済みテーマを描画前に適用（ちらつき防止）。
2. タグ類・noteID 表示・取得設定を復元。
3. フィードのキャッシュがあれば即表示（「前回取得した記事一覧を表示中」）。
4. コメントを自動取得（noteID も登録記事もなければ何もしない）。
5. クリエイターが登録済みならフィードを自動取得（コメント取得を優先）。
6. ログイン完了後、まだコメント取得が始まっていなければ取得を実行。

### 4.5 表示テーマ

- `auto`（端末設定に追従）/ `light` / `dark` の3種。
- CSS 変数で配色を定義。アクセントカラーはピンク `#F2A0B5`。
- 設定は保存・同期される。

## 5. データ通信

### 5.1 CORS プロキシ

note API はブラウザから直接叩けないため、以下のプロキシを経由する（優先度順）。

1. **自前 Cloudflare Worker**（`notebiyori-proxy`）— メイン。URL は `index.html` の定数 `NOTEBIYORI_PROXY_URL` 1か所で管理し、空文字のあいだは使わない
2. `r.jina.ai`（`x-respond-with: text` ヘッダー付き）
3. `proxy.cors.sh`
4. `api.codetabs.com`
5. `api.cors.lol`
6. `api.allorigins.win`
7. すべて失敗したら直接 fetch を最後に試す

2〜6 の公開プロキシは予備として残している。

#### 自前 Worker の仕様

| 項目 | 内容 |
| --- | --- |
| 形式 | `{NOTEBIYORI_PROXY_URL}/?url={エンコードした note API URL}` |
| メソッド | `GET` と `OPTIONS`（プリフライト）のみ。それ以外は 405 |
| 中継できる URL | `https://note.com` の 5.2 の4種類のパスのみ。それ以外は 403 |
| Origin 制限 | `https://kyownruby.github.io`、`http://localhost[:port]`、`http://127.0.0.1[:port]` のみ。それ以外・Origin なしは 403 |
| レスポンス | note のステータスコードと JSON をそのまま返し、許可 Origin に `Access-Control-Allow-Origin` を付与 |
| キャッシュ | プロフィール（`/api/v2/creators/{urlname}`）の成功レスポンスのみ 10 分。記事一覧・記事情報・コメントはキャッシュしない。`_t` は転送先とキャッシュキーから除外 |
| note へのリクエスト | 一般的なブラウザの User-Agent を付与 |

詳細と再デプロイ手順は `worker/README.md` を参照。

#### 制御ロジック

| 項目 | 値・挙動 |
| --- | --- |
| 同時リクエスト数 | 全体で最大4 |
| リクエスト間隔 | 250ms 以上空ける（レート制限対策） |
| タイムアウト | 1リクエスト15秒 |
| リトライ | 全プロキシ失敗時に 1秒後・3秒後の計2回再試行 |
| キャッシュ回避 | URL に `_t={timestamp}` を付与、`cache: 'no-store'` |
| 失敗判定 | HTTPエラー / 空レスポンス / `{` で始まらない（JSONでない）レスポンス |
| プロキシ選択 | 連続失敗数の少ない順。同数なら自前 Worker を先に、公開プロキシ同士はローテーションで負荷分散 |
| 健全性の記憶 | 連続失敗数を `nc_proxy_health` に保存し、24時間有効 |

### 5.2 利用している note API

| 用途 | エンドポイント |
| --- | --- |
| クリエイター情報 | `GET https://note.com/api/v2/creators/{urlname}` |
| 記事一覧 | `GET https://note.com/api/v2/creators/{urlname}/contents?kind=note&page={n}&per=20` |
| 記事情報 | `GET https://note.com/api/v3/notes/{key}` |
| コメント一覧 | `GET https://note.com/api/v3/notes/{key}/note_comments` |

## 6. データ保存と同期

### 6.1 localStorage

| キー | 内容 | 同期 |
| --- | --- | --- |
| `nc_note_id` | 自分の noteID | ○ |
| `nc_note_profile` | 自分の表示名・アイコンのキャッシュ | × |
| `nc_theme` | 表示テーマ | ○ |
| `nc_fetch_mode` | 取得モード（`count` / `all`） | ○ |
| `nc_fetch_count` | 取得件数 | ○ |
| `nc_registered` | URLで個別登録した記事 | ○ |
| `nc_replied` | 「返信済み」にしたコメントkey | ○ |
| `nc_checked` | 確認済み記事ID（現在は追加する操作がなく、過去データの表示・同期のみ） | ○ |
| `nc_creators` | フィードのクリエイター一覧（並び順込み） | ○ |
| `nc_read_feeds` | 既読にした記事ID | ○ |
| `nc_expanded_groups` | 開いているグループ | ○ |
| `nc_hide_read` | 既読を非表示 | ○ |
| `nc_feed_cache` | フィード取得結果のキャッシュ | × |
| `nc_proxy_health` | プロキシの連続失敗数 | × |

### 6.2 Firebase 同期（ログイン時のみ）

- 認証：Firebase Authentication（Google）。
- 保存先：Firestore `users/{uid}` ドキュメント1件に全状態を保存。
- 送信タイミング：状態変更から1.5秒後にまとめて保存（デバウンス）。ログアウト前にも未送信分を保存。
- ログイン直後のマージが終わるまでは送信しない（`syncReady`）。

#### ログイン時のマージ規則

| データ | 規則 |
| --- | --- |
| 返信済み・確認済み・既読・開いているグループ | ローカルとリモートの和集合 |
| クリエイター一覧・登録記事 | リモートの順番を優先し、ローカルだけにあるものを末尾に追加 |
| 既読を非表示・テーマ・取得モード・件数 | リモート優先 |
| noteID | リモート → ローカル → 未登録ならプロンプトで入力 |

- マージ結果は localStorage に書き戻し、その後クラウドにも保存。
- 読み込みに失敗した場合は「Firestoreのセキュリティルールを確認してください」とアラート。

## 7. 既知の注意点

- note API・CORS プロキシはいずれも非公式／外部サービスのため、仕様変更や停止で取得できなくなる可能性がある。
